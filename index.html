The problem

Why multi-site reporting breaks

Nobody buys a dashboard. They buy the ability to rank their sites and trust the order.

With one site, reporting is arithmetic. With fifteen, it's a definitions problem. Every site keeps its own workbook, and each one defines the measures slightly differently — so the same word means a different number depending on who you ask. There is no single source of truth, only fifteen versions of it. I build that source: every measure defined once, in one place, applied to every site.

Roll-ups that don't reconcile The portfolio total doesn't equal the sum of the sites, and nobody can say which one is wrong.
Unfair comparisons Sites of different sizes ranked on raw totals, so the biggest always looks best and the ranking tells you nothing.
Slow site onboarding A new location takes weeks to appear in reporting because someone has to hand-wire it in.
Fifteen versions of one file Access managed by emailing different workbooks to different managers, with no way to know who has what.
Practice areas

How the work is organised

Engagements usually start in one area and expand into the next. The order is deliberate — governance is worth very little sitting on a pipeline nobody trusts.

01

Data Platform Architecture

Getting every site's data into one governed place automatically, so reporting stops depending on each location remembering to send a file.

  • Microsoft Fabric Lakehouse and pipelines
  • Medallion architecture: bronze, silver, gold
  • REST API and SharePoint ingestion, OAuth 2.0
  • Unattended refresh with error handling
02

Conformed Multi-Site Modelling

The layer that decides whether your sites can be compared. Metrics defined once, conformed across every location and subject area.

  • Kimball dimensional modelling, conformed dimensions
  • Site, date, account and department conformity
  • Weighted aggregation so comparisons are fair
  • Tie-out reporting against the source system
03

Treating reporting as production software — versioned, reviewable, promotable, and safe for more than one person to maintain.

  • Deployment pipelines across dev, test, production
  • .pbip project format with Git version control
  • Metadata documentation and governed datasets

Role-specific views built on one shared model, so the board pack and the site manager's screen can never disagree.
