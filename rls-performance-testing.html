How to test RLS performance in Power BI

By Zohal Zahir · November 2026 · From the series Who sees what: RLS in Power BI

ShareLinkedInFacebookXEmail

The problem. RLS is set up. Did you check what it costs your report?

Why. RLS adds a filter to every DAX query, so it can slow visuals down.

Quick check, in Power BI Desktop (Performance Analyzer):

  1. Start recording, refresh visuals, and note each visual's DAX query time with no role.
  2. Modeling → View as → pick the role.
  3. Record again. The gap for each visual is what RLS costs.

Deeper check, in DAX Studio:

  1. Connect to the model. You connect as an admin, so RLS is off until you turn it on.
  2. On the Advanced tab, use View As: pick the role, and for dynamic RLS enter a real email from the security table.
  3. Turn on Server Timings. Clear the cache before each run.
  4. Compare storage engine time and query count, with and without the role. A big jump there means expensive relationship joins.

Making it faster:

  • Filter dimension tables, not the fact table.
  • Use relationships in the rule, not LOOKUPVALUE over big tables.
  • Use two-way filtering only on small tables. Security ↔ DimRegion both ways is fine because both tables are tiny.
  • Keep the security table small, with integer keys.
  • On DirectQuery, tune the source (indexes).
  • Only a few fixed audiences? Separate models can beat RLS.

Check before go-live

  • Main pages were timed with and without each role
  • Two-way filtering is only on the small security relationship Desktop
